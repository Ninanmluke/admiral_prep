# Foundations browser lab

## Goal

Use GitHub.com to make one focused documentation change and move it through a branch, commit, pull request, and review.

## Exercise

Work in pairs. Create one branch and pull request per pair.

Before editing:

- Use the writable organization-approved work repository supplied by your facilitator or administrator, with your approved GitHub identity.
- The [owned reference](https://github.com/johnsont1693/scientific-workflow-workshop) is private and read-only for learners. Authorized read access is required; do not create exercise branches or pull requests there.
- For managed user accounts, an authorized facilitator or administrator stages an internal organization-owned copy. Do not bypass access controls with personal accounts or public forks.
- Pair with an enabled participant or observe if access is not available. GitHub handles are collected only when needed to provision the approved work repository.

1. Open `checks/expected-output.md`.
2. Select **Edit this file**.
3. Add this sentence beneath the expected record count:

   > Reviewers should confirm the count against the approved requirement before accepting a change.

4. Choose **Create a new branch for this commit and start a pull request**.
5. Name the branch:

   ```text
   foundations/<pair-id>-review-note
   ```

   Replace `<pair-id>` with the unique identifier supplied by your facilitator.

6. Use this commit message:

   ```text
   Document the human count-verification step
   ```

7. Open the pull request and complete the template.
8. Exchange pull-request links with a partner who can access the same repository or copy.
9. Review your partner's diff and leave one evidence-based comment.
10. Review available validation results and check that no secrets or sensitive content were added. If Actions is unavailable, use facilitator-provided local validation evidence and record the limitation; never bypass a required gate.

## Success criteria

- One focused change
- A branch with a unique name
- An intent-focused commit message
- A complete pull-request description
- One human review comment tied to the requirement or expected output

Do not merge unless the facilitator authorizes it and all required human review, security, and test gates are satisfied. This lab remains browser-based and does not require Copilot or a local development environment.
